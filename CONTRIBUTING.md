# Contributing

Use the correction issue template to identify the release/package hash, exact
record or instance, proposed correction and evidence. Distinguish source error,
software error, identity conflict, HS reasoning and missing facts. Do not merge
products because names or HS codes match. Preserve uncertainty and original scope.

Do not post credentials, private source material, personal contact data or
restricted excerpts. Link eligible public evidence instead. New source material
needs its own attributable terms and provenance. No contribution automatically
changes human review state or grants redistribution rights.

Run `python3 -m unittest discover -s tests -v`. Fixtures must be labelled synthetic
and cannot count as research observations. v0.1.0 release preparation changes
only blocking packaging/usability defects; scientific improvements go to v0.2.
